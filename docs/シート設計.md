# スプレッドシート設計

最終更新: 2026-08-15

対象スプレッドシート: 見積もりフォームの回答が蓄積されている既存シート
（ID はスクリプトのプロパティ `BOARD_SPREADSHEET_ID` ではなく、バインド先として自動解決）

**このファイルはシート構造を変更するたびに必ず更新する。**

---

## タブ一覧

| タブ | 役割 | 作成元 |
|---|---|---|
| 案件ボード | 進行中の案件一覧。ここだけ見れば回る | 新規 |
| 顧客 | 顧客マスタ。請求・返送に必要な情報を保持 | 新規 |
| メール履歴 | AI返信案と送信済み文面の記録（②で使用） | 新規 |
| テンプレ | メール文面 T1〜T7 | 新規 |
| ナレッジ | 回答方針メモ・返信実例（②で使用） | 新規 |
| 設定 | 発送先・通知先などの値 | 新規 |
| ログ | 実行履歴 | 新規 |
| `Config` | **既存。見積もりフォームの設定JSON。変更禁止** | 既存（非表示） |
| `Responses` | **既存。フォーム回答の生データ。変更禁止・読み取りのみ** | 既存（非表示） |

既存2タブはフォームが読み書きしているため一切変更しない。
案件・顧客の行は `Responses` を**読み取って**生成する。

## 案件ボード

1行＝1案件。A〜G列が常時表示（見やすさ優先）、H列以降は詳細。

| 列 | 項目 | 種別 |
|---|---|---|
| A | 案件ID | 自動（`A001`〜） |
| B | ステータス | プルダウン＋色分け |
| C | お客様 | 自動（顧客タブから） |
| D | 予定点数 | 任意入力。空欄なら案内メールの点数行が自動で消える |
| E | 初回ご依頼予定数 | 自動。見積もり回答へのご返信から取り込む |
| E | 受付開始日 | **★手入力必須** |
| F | 納期予定（自） | **★手入力必須** |
| G | 納期予定（至） | 任意。入れると「◯月◯日 〜 ◯月◯日」と範囲で案内する |
| H | 次にやること | **数式で自動表示** |
| I | 顧客ID | 自動 |
| J | 依頼内容 | 自動（フォームで選ばれたプラン内容） |
| K | フォームの問い合わせ内容 | 自動。フォーム回答の記入内容。**あとから変わらない** |
| L | 最新のメール内容 | 自動。最後に届いたメールの本文で更新される |
| M | 単価 | 自動（フォーム回答） |
| N | 請求書送付日 | 自動（Square請求書の送信確認時） |
| O | Square請求書ID | 自動（請求書の下書き作成時、または顧客から検索して紐づけ） |
| P | 署名・支払確認日 | 自動（支払いと署名がそろったとき）／手入力 |
| Q | 追跡番号 | 自動抽出／手入力 |
| R | 案内メール作成日 | 自動（下書き作成時） |
| S | 最終連絡日 | 自動 |
| T | メモ | 手入力 |
| U | 元回答行 | 自動（`Responses` の行番号。重複取込の防止） |

3つの内容を別の列に分けている。

| 列 | 中身 | 変化 |
|---|---|---|
| 依頼内容 | 撮影・クリーニングなど**選ばれたプラン** | フォーム回答時のまま |
| フォームの問い合わせ内容 | フォームで**お客様が書いた文章** | フォーム回答時のまま |
| 最新のメール内容 | **最後に届いたメールの本文** | メールが届くたび更新 |

どちらの文章列も400文字を超えると切り詰め、全文はメール履歴の `要約` 列に残る。
過去のやりとりは「対応を選ぶ」画面の「このお客様の過去のお問い合わせ」で読める。

### 最新のお問い合わせ内容の更新（`boardRefreshInquiries_`）

**返信案の生成とは切り離してある。** 返信案は一度処理したスレッドを二度と読まないため、
そこに相乗りさせると既存のメールがいつまでも反映されない。

- 顧客タブのアドレス（最大30件）を `{from:a from:b …}` の形で**まとめて1回だけGmail検索**する
- 顧客ごとに**最後に届いたメール**を選び、引用を除いた本文を書き込む
- `最終連絡日` は、そのメールの日時が既存の値より新しいときだけ更新する
- メールが1通も無い案件は、フォームの「お問い合わせ内容・補足」で埋める
- 内容が変わっていない行は書き込まない

自動確認と「新着を今すぐ確認する」の両方で実行する。

### ステータスと色

| ステータス | 色 | 意味 |
|---|---|---|
| 問合せ | アンバー | フォーム回答直後。未返信 |
| 返信済 | アンバー | こちらから返信済み。相手待ち |
| 依頼確定 | パープル | 受注。案内メール未送付 |
| 支払い情報登録・契約書署名待ち | ブルー | 案内メールと請求書を送付済 |
| 発送済み | グリーン | お客様が発送済み。作業チームへの共有待ち |
| 発送待ち | ティール | 手続き完了。商品の到着待ち |
| 作業中 | グレー | 商品到着済 |
| 返送済 | グレー | 完了 |
| 見送り | グレー | 失注・中止 |

### G列「次にやること」の判定

ステータスと日付から自動で文章を生成する。放置案件は赤字。

| 条件 | 表示 |
|---|---|
| 問合せ | 返信案を確認して返信 |
| 返信済 | お客様の返信待ち |
| 依頼確定 かつ 日付未入力 | 日付を入れて案内メール |
| 依頼確定 かつ 日付入力済 | 案内メールを送る |
| 支払い情報登録・契約書署名待ち かつ 署名・支払確認日が空 | 支払い情報の登録・署名待ち（N日経過） |
| 支払い情報登録・契約書署名待ち かつ 署名・支払確認日あり | **手続き完了のご連絡を送る**（赤字） |
| 発送待ち | 追跡番号の連絡待ち |
| 作業中 | 作業 〜M/D |

## 顧客

1行＝1顧客。**キーはメールアドレス**。同じアドレスからの再問い合わせは既存行を更新する。
Square の請求書作成と返送に必要な情報を保持し、一覧で確認・修正できる。

| 列 | 項目 | 種別 |
|---|---|---|
| A | 顧客ID | 自動（`C001`〜） |
| B | 会社名・屋号 | フォーム／**お客様の返信から自動** |
| C | 担当者名 | フォームから自動／修正可 |
| D | メールアドレス | フォームから自動（**キー**） |
| E | 電話番号 | フォームから自動／修正可 |
| F | ストア名 | **お客様の返信から自動** |
| G | 代表者名義 | **お客様の返信から自動** |
| H | 請求先 郵便番号 | **お客様の返信から自動** |
| I | 請求先 住所 | **お客様の返信から自動** |
| J | 返送先 郵便番号 | **お客様の返信から自動** |
| K | 返送先 住所 | **お客様の返信から自動** |
| L | 返送先 宛名 | **お客様の返信から自動** |
| M | 返送先 電話番号 | **お客様の返信から自動** |
| N | 依頼内容 | フォームから自動／修正可 |
| O | 月間予定数 | フォームから自動 |
| P | 単価 | フォームから自動／修正可 |
| Q | 初回問い合わせ日 | 自動 |
| R | 最終更新日 | 自動 |
| S | メモ | 手入力 |
| T | Square顧客ID | 請求書作成時に自動 |

Square の請求書送付に**必須なのはメールアドレスだけ**（公式ドキュメントで確認済み）。
氏名・会社名・電話番号・住所はいずれも任意で、姓名を分ける必要もない。
会社名や氏名は請求書と契約書の宛名として使うため、実務上は入れておく。

### お客様の返信からの自動取り込み

見積もり回答（T1）で下記の見出しを送り、返信に同じ見出しがあれば該当列へ書き込む。
定義は `BOARD_CUSTOMER_INTAKE`（board.js）。

`ストア名` / `会社名` / `代表者名義` / `請求先郵便番号` / `請求先住所` /
`返送先郵便番号` / `返送先住所` / `返送先電話番号` / `宛名`

`初回ご依頼予定数` だけは顧客ではなく**案件**に保管する（`BOARD_CASE_INTAKE`）。
「対応を選ぶ」→「依頼確定」で予定点数が未入力のとき、この値から数字を取り出して初期値にする。
「50点」「約50」「１００点」のような書き方でも数値として読み取る。

- 見出しは全角・半角どちらのコロンでもよく、行頭の `・` や引用記号 `>` は無視する。
- 括弧書きの補足（例：`会社名（個人事業主の方は個人名義）`）は取り除いて照合する。
- **値が空の行は無視する**ため、引用された空欄のテンプレートで既存の値が消えることはない。
- 既存の値と違う場合は上書きし、更新した項目名をログに残す。

## 返信実例（②の学習用）

承認して下書きに保存した時点で1行追加される。

| 列 | 項目 |
|---|---|
| A | 日時 |
| B | 顧客 |
| C | 件名 |
| D | AI初回案 |
| E | 修正指示 |
| F | 最終文面 |
| G | 抽出した方針 |

G列は、初回案と最終文面に差があるとき、AIが「次回に活かせる行動指針」を1〜2行で抽出したもの。
抽出結果はナレッジタブへ `学習（要確認）` として自動追記される。

> **学習がテンプレを書き換えることはない。**
> 学習の書き込み先は「返信実例」と「ナレッジ」の2つだけで、テンプレシートには一切触れない。
> テンプレを変更するのは、人の手による編集と、初期セットアップ時の移行処理のみ。
> また T1〜T7 の定型文はテンプレをそのまま差し込むだけでAIを通さないため、
> 学習の内容によって文面が変わることもない。AIが関わるのは「通常の返信」だけ。
**誤った学習が入る可能性があるため、ナレッジタブの「学習（要確認）」行は定期的に目視し、
不要なら削除・修正する。**

## テンプレ

**縦横を入れ替えた構成。** 1列が1通のメールで、横に並べて見比べられる。

| 行 | 項目 | 内容 |
|---|---|---|
| 1 | 項目 | A列が見出し、B列以降にテンプレートID（T1〜T7・S1） |
| 2 | 名称 | |
| 3 | 件名 | |
| 4 | 本文 | `{{変数}}` を含む。**行の高さ500px固定** |
| 5 | 備考 | |

1行目と1列目は固定表示。各テンプレートの列幅は360px、折り返し・上揃え。
テンプレートを追加するときは、右端に1列足して1行目にIDを入れる。

### 差し込み変数のうち、条件付きで消える行

| 変数 | 消える条件 |
|---|---|
| `{{予定点数}}` | 予定点数が空欄のとき、その行ごと削除 |

初期セットアップは、既存の T2・T4 に納期の注意書きが無ければ、
納期行の直後へ次の2行を自動で差し込む（既存の本文はそれ以外変更しない）。

```
　※上記受付開始日に到着した際のおおよその目安です。
　※初回のみ、ストア情報登録のため、通常より大幅に納期をいただいております。
```

どちらも常に本文へ含める固定文。**初回かどうかで出し分ける処理は行わない。**
不要な案件では、返信案の本文から手で消す。
旧仕様の `{{初回注記}}` が残っている本文は、この固定文へ自動で置き換える。

内容は [メールテンプレート.md](メールテンプレート.md) と同期する。
**シート側が運用上の正**とし、変更したらこのドキュメントにも反映する。

## ② メール返信支援（mail.js）

```
10分ごとのトリガー（Google のサーバー上で実行。PCの電源は不要）
  ├ Responses の未取込行から顧客・案件を作成
  └ 顧客タブのアドレスごとに Gmail を検索
      条件: 直近30日 / ラベル「ササゲパス/返信案作成済」が付いていない
      ├ 該当なし → 終了（Claude API は呼ばない＝費用ゼロ）
      └ 該当あり かつ スレッドの最新メールが顧客からのもの
            ├ 回答方針（ナレッジ）＋ 直近の返信実例 ＋ 案件状況 ＋ スレッド全文 を Claude に渡す
            ├ メール履歴タブに「未確認」として1行追加（この時点では下書きにしない）
            ├ スレッドにラベルを付けて処理済みにする
            └ 通知先アドレスへ「返信案の全文＋シートへのリンク」をメール送信
```

### フォーム回答も対応リストに載る

見積もりフォームに回答があった時点で、メール履歴へ「未確認」の行を1件作る。
**お客様からメールが届くのを待たないため、初回の返信が漏れない。**

- 対応種別は未選択。要約欄にフォームの問い合わせ内容と選択内容が入る。
- GmailスレッドIDは空。承認時は返信ではなく**新規メールの下書き**を作る。
  件名は対応種別のテンプレートのものを使う。
- この行の作成時点ではAIを呼ばない（費用ゼロ）。

**手動実行（新着を今すぐ確認する）は通知メールを送らない。**
画面を見ている前提のため、結果はダイアログに出したうえで「対応を選ぶ」画面を開く。

### 確認画面（メニュー「対応を選ぶ」）

モーダルダイアログで開く。左に確認待ちの一覧、右に対応種別・本文編集欄。

| 操作 | 動作 |
|---|---|
| どの状況での対応か | 対応種別を選ぶ（初期は未選択）。選ぶだけでは文面は変わらない |
| この対応で返信案を作る | テンプレートと問い合わせ内容をもとに、AIが返信案を作る |
| 本文を直接編集 | テキストエリアでそのまま書き換えられる |
| AIに修正を依頼 | 指示文を入れて実行。指示は修正指示ログへ蓄積される |
| 最初から作り直す | AIに再生成させる。過去の修正指示は引き継ぐ。状態は「未確認」に戻る |
| この内容で下書きに保存 | Gmailの同スレッドに下書きを作成し、案件ステータスを更新。返信実例へ記録・方針を抽出 |
| 編集内容だけ保存 | シートにだけ保存（下書きは作らない） |
| 対応不要 | 一覧から外す |

### 対応種別と、同時に必要な処理

`BOARD_RESPONSE_TYPES`（board.js）で定義。選ぶと画面に「同時に必要な処理」が表示され、
下書き保存時に案件ステータスが自動更新される。

初期状態は**未選択**。選ぶと、その対応に必要な入力欄と操作が**同じ画面に追加表示される**。
別のメニューへ移動する必要はない。

文面は選んだだけでは変わらない。**［この対応で返信案を作る］を押すと、
テンプレートを土台に、お客様の問い合わせ内容へ合わせた返信案をAIが作る。**
テンプレートの料金・納期・住所などは一字一句そのまま残すよう指示している。
「通常の返信」を選んだ場合はテンプレートを渡さず、方針と実例だけで書く。

| 対応種別（画面表示名） | 本文 | 案件ステータス | 追加で表示される操作 |
|---|---|---|---|
| 通常の返信（AIが問い合わせ内容に応じて回答します） | AI生成 | 返信済 | なし |
| 見積もり回答（料金・納期の目安・ご利用条件をお伝えします） | T1 | 返信済 | なし |
| 依頼確定（受付開始日・納期を回答し、依頼内容・支払い・発送に関する事項を伝えます） | T2 | 支払い情報登録・契約書署名待ち | 受付開始日**（必須）**／納期予定 自**（必須）**・至／予定点数 ＋ **初回登録の請求書の作成・送信** |
| 手続き完了（支払いと署名の確認をお伝えし、発送をご案内します） | T4 | 発送待ち | 署名・支払確認日 |
| 手続きの催促（支払い・署名がお済みでない方へご確認をお願いします） | T5 | 変更なし | なし |
| 発送の催促（発送状況の確認と、追跡番号のご連絡をお願いします） | T6 | 変更なし | なし |
| お預かり完了（商品の到着と点数をお知らせし、納期の目安を再度お伝えします） | T7 | 作業中 | 予定点数（実際の到着点数に更新） |

- 対応する案件は、そのお客様の最新の案件（返送済・見送りを除く）を自動で選ぶ。
- **必須の入力欄が埋まるまで「この内容で下書きに保存」は押せない。**
- 定義は `BOARD_RESPONSE_TYPES` と `BOARD_CASE_FIELDS`（board.js）。

- **下書きは承認したときにだけ作られる。** 自動では作らない。
- **自動送信は実装しない。**

### やり直したいとき

| 状況 | 対処 |
|---|---|
| Gmailの下書きを消してしまった | 一覧に残っているので、そのまま「この内容で下書きに保存」を押し直す |
| 返信案そのものを作り直したい | 「最初から作り直す」を押す |
| 一覧から消えている（送信済／対応不要） | メール履歴タブの `状態` 列を手で `未確認` に書き換えると一覧に戻る |

同じスレッドを②が二重に拾わないよう、処理済みのスレッドには Gmail ラベル
`ササゲパス/返信案作成済` が付く。**新着として再検知させたい場合はこのラベルを外す。**
- 1回の実行で作る返信案は最大5件（暴走防止）。
- モデルは `claude-sonnet-5`。スレッド本文は直近4000文字までに制限。
- 料金・納期など方針に書かれていない情報は創作しないようシステムプロンプトで指示している。

## メニュー操作

スプレッドシート上部の「ササゲパス」メニュー。

| 項目 | 動作 |
|---|---|
**日常的に使うもの**

| 項目 | 動作 |
|---|---|
| 対応を選ぶ | 確認待ちの返信案を開き、対応種別を選んで下書きにする。**日程の入力と請求書の作成もこの画面で完結する** |
| 新着を今すぐ確認する | **フォーム回答の取り込み**と**メールの確認・返信案生成**をまとめて実行。結果はダイアログに表示し、**通知メールは送らない** |
| 新着確認の状態を見る | 自動確認の稼働状況・通知先・APIキー・確認待ち件数を一覧表示 |

**別途対応メニュー（サブメニュー）** — お客様からのメールが無い案件のための予備。
通常は「対応を選ぶ」だけで完結する。

| 項目 | 動作 |
|---|---|
| 受付開始日・納期・点数だけを入力する | 案件のサイドパネルを開く |
| 初回登録の請求書だけを作成・送信する | Square手続き画面を開く |

「新着メールを今すぐ確認する」と「対応を選ぶ」は役割が違う。
前者は**Gmailから取り込んで案を作る**、後者は**できた案を確認して下書きにする**。
自動確認を有効にしていれば前者は普段使わない。

**設定（サブメニュー）**

| 項目 | 動作 |
|---|---|
| 初期セットアップ | タブの作成と旧レイアウトからの移行（何度実行しても既存データは壊さない） |
| Anthropic APIキーを登録する | スクリプトプロパティへ保存 |
| 新着メールの自動確認を開始／停止する | 10分ごとの時間トリガーを作成／削除 |
| Squareトークンを登録する | スクリプトプロパティへ保存 |
| 過去の請求書の設定を読み取る | 既存の請求書設定を個人情報を伏せて抽出 |
| フォーム回答だけを取り込む | `Responses` の未取込行から顧客・案件を作成（通常は自動確認に含まれる） |
| 顧客・案件を作り直す | 案件ボードと顧客を全消去して再取込（手入力値も消えるため確認ダイアログあり） |

`Responses` の読み取りは**列の位置ではなく見出し名**で解決する（`BOARD_SOURCE_FIELDS`）。
列が増減しても取り違えない。メールアドレスとして妥当でない行は取り込まない。

## Square 連携（square.js）

アクセストークンはスクリプトプロパティ `SQUARE_ACCESS_TOKEN` に保管する。

### 登録手数料の請求内容

過去の請求書（`000014` / `000016` / `000022`）から抽出した実績値をそのまま使用する。

| 項目 | 値 |
|---|---|
| 店舗 | ササゲパス（`L11Z7FV5M0N4X`） / JPY |
| 品目 | 登録手数料 × 1 |
| 単価 | 200円（税抜） |
| 税 | 消費税 10.0%・ADDITIVE・LINE_ITEM → 合計220円 |
| タイトル | サービスご利用における決済情報のご登録とご署名に関するお願い |
| メッセージ | テンプレ `S1`（過去の文面と完全一致。空行・全角空白まで再現） |
| 送付方法 | EMAIL |
| 支払方法 | カードのみ（ギフトカード・銀行振込・後払い・Cash App はすべて無効） |
| カード情報の保存 | 有効（`store_payment_method_enabled: true`） |
| 支払期限 | 発行日の2日後 |
| チップ | 無効 / 自動支払い なし / リマインダー なし |

### 契約書は API から扱えない（確認済み）

Square の公開APIに **Contracts API は存在しない**。請求書の `attachments` は画像とPDFのファイル添付専用で、
電子署名付きの「Square 契約書」を添付する手段はない。契約書はダッシュボード専用機能である。

契約書の事前作成は不要。**請求書の編集画面でその場で新規作成して添付する**。
（添付ファイルとカスタムフィールド → Square 契約書 → 新規の契約書 → サービス利用規約 → 保存）

### 手続き画面（メニュー「Squareの手続きを進める」）

案件ボードで行を選んで開くモーダル。2段階を順に進め、完了した段階は緑で表示される。

| # | 内容 | 担当 | 記録先 |
|---|---|---|---|
| 1 | Square顧客の作成（既存があれば流用）＋ 請求書を DRAFT で作成 | **自動** | 顧客タブ `Square顧客ID` / 案件 `Square請求書ID` |
| 2 | 契約書を添付して送信 | 手動 | 案件 `請求書送付日` |

- 手順2の説明文は**設定タブの「請求書送信の手順」で編集できる**。
  Square の画面が変わったらここを書き換える。
- 手順2の「送信しました」は、**Square側の請求書状態を実際に確認**してから記録する。
  まだ DRAFT のままなら記録せずエラーを返すため、送信し忘れたまま先に進むことがない。
- 手順1が終わるまで手順2のボタンは押せない。

### 支払いと署名の完了確認（自動）

`squareCheckCompletions`（square.js）。自動確認と「新着を今すぐ確認する」の両方から実行する。
対象は**ステータスが「支払い情報登録・契約書署名待ち」かつ署名・支払確認日が空**の案件のみ。

| 確認したいこと | 方法 |
|---|---|
| 220円の支払い | Square APIで請求書のステータスを取得し `PAID` / `PARTIALLY_PAID` を判定 |
| 契約書への署名 | Square から届く署名完了メールをGmailで検索 |

案件に `Square請求書ID` が無い場合（Squareの画面で直接作った請求書など）は、
メールアドレスからSquareの顧客を探し、その顧客宛の登録手数料の請求書を検索して紐づける。
見つかったIDは案件へ書き戻すので、次回以降は検索しない。
それでも見つからない案件はログに理由を残す。

署名メールの判定条件:

- 差出人が `noreply@messaging.squareup.com`
- 件名に「署名されました」を含む
- 件名か本文に、**その顧客を見分ける文字列のいずれかを含む**

契約書はSquare上の顧客に対して発行されるため、業務ボードに登録した連絡先と
**メールアドレスが違うことがある**。そのため次を手がかりにする。

- 顧客タブのメールアドレスと担当者名
- Square側の顧客のメールアドレス・氏名・会社名（`Square顧客ID` からAPIで取得）

比較のときは空白を落とし、3文字未満の手がかりは使わない（取り違え防止）。

両方そろったときだけ `署名・支払確認日` に署名日を記録し、次の2つで連絡を促す。

- 案件ボードの「次にやること」が **「手続き完了のご連絡を送る」** に変わり赤字になる
- 通知先アドレスへ「手続き完了。発送のご案内を送ってください」とメールを送る

片方だけでは記録しない。支払いだけ済ませて署名を忘れる、あるいはその逆を見逃さないため。

## 発送の検知と作業チームへの共有（shipping.js）

`shipCheckAll`。自動確認と「新着を今すぐ確認する」の両方で実行する。
対象は**ステータスが「発送待ち」または「支払い情報登録・契約書署名待ち」**の案件。

```
その顧客からの最新メールを取得
  └ 前回と同じメールなら何もしない（同じ内容をAIに繰り返し読ませない）
      └ Claude が本文と添付画像を読み、次を判定
          shipped   発送されたか（発送予定・検討中は false）
          tracking  追跡番号（本文になければ送り状の写真から）
          quantity  発送された点数
          arrival   到着予定
          notes     作業上の特記事項
```

発送と判定されたときだけ、次を行う。

- `追跡番号` に番号を記録
- ステータスを **発送済み** に変更
- `作業チーム共有` 列に共有内容をまとめる
- 「次にやること」が **作業チームへ共有する** に変わり赤字になる

### 作業チーム共有の内容

**料金は載せない。** 依頼内容から `（¥400/点）` のような価格表記を取り除く。

```
【作業依頼】A005　古川 裕規

■ 追跡番号
　123456789012
　https://toi.kuronekoyamato.co.jp/cgi-bin/tneko?number=123456789012
　到着予定: 8月19日

■ 点数
　10点

■ 納期予定
　2026年8月25日 〜 2026年8月28日

■ 作業内容
　・クリーニング：スチームアイロン
　・クリーニング：簡易洗浄
　・撮影：白抜き・正方形撮影

■ お客様からの指定
　手を加えてほしくない商品はありません
```

送信はしない。この列をコピーして、任意の手段でチームへ渡す。

### 手続き完了の連絡について

支払いと署名がそろった時点で**ステータスを自動的に「発送待ち」へ進める**。
発送先は案内メール（T2）で伝え済みのため、完了の連絡は行わない。
対応種別の「手続き完了」は選択肢としては残すが、「次にやること」では促さない。
