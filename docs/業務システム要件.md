# ササゲパス業務システム 要件定義

最終更新: 2026-08-14

問い合わせ対応と案件管理を、1つのスプレッドシートに集約して半自動化する。
このドキュメントは Claude Code セッションから随時確認・更新する前提で管理する。

---

## 1. 目的

| # | やりたいこと | 状態 |
|---|---|---|
| ① | サイト Q&A に補償方針を追記 | **完了**（2026-08-13 公開） |
| ② | 問い合わせメールの返信案を自動生成し、下書きとして提示する | 要件定義中 |
| ③ | 依頼確定後の案内メール送付までを半自動化し、進捗を一覧化する | 要件定義中 |

②と③は同一のスプレッドシート上で管理・操作する。

## 2. 決定事項

| 項目 | 決定 |

## 3. システム構成

```
[既存] 見積もりフォーム（GASウェブアプリ / Google Sites 埋め込み）
          │ 追記
          ▼
   スプレッドシート「ササゲパス業務ボード」
   ├── 案件一覧      1行＝1顧客案件。ステータス・変数・請求書URL・次アクション
   ├── メール履歴    1行＝1通。AI返信案・下書き状態・実際に送信した文面
   ├── テンプレ      案内メール等の雛形（変数入り）
   ├── ナレッジ      回答方針メモ・サイトQ&A自動取込・過去返信の実例
   ├── 設定          発送先・納期日数・単価表・通知先
   └── ログ          実行履歴
          │
          ├─ ② Gmail 監視 → Claude API → 返信下書き ＋ 通知メール
          └─ ③ メニュー操作 → 変数入力 → 案内メール下書き
```

**②と③を同一シートに置く理由**: メールの差出人アドレスで案件一覧と自動的に紐づく。
「この相手は既に依頼確定済み、納期は◯日」という文脈を AI に渡せるため、返信案の精度が上がる。

## 4. ② メール返信支援

### 処理の流れ

```
定期トリガー（頻度は運用に合わせて調整。既定は10分ごと）
  └ Gmail を検索：未処理の問い合わせはあるか？   ← 1秒未満・無料
      ├ なし → 即終了（AI は呼ばない）
      └ あり → Claude API で返信案を生成
                ├ Gmail の同一スレッドに返信下書きを保存（差出人 info@）
                ├ 自分宛に通知メールを送信
                └ メール履歴シートに行を追加
```

- AI のコストは受信メール件数にのみ比例する。トリガー頻度とは無関係。
- トリガー頻度が決めるのは「届いてから下書きができるまでの待ち時間」のみ。
- 手動実行用の「今すぐ確認」メニューも用意する。

### 通知メールの内容

- 件名: `【要対応】◯◯様から返信 ─ 返信案を作成しました`
- 本文: 相手のメールの要約 / AI 返信案の全文 / Gmail 下書きを開くリンク / シートを開くリンク

### 段階導入

| | 作るもの | 得られる状態 |
|---|---|---|
| Phase 1 | 新着検知 → 返信案生成 → 下書き保存 → 通知。参照情報は「回答方針メモ」1枚 | これだけで実用になる |
| Phase 2 | サイト Q&A・料金表を自動取込 | 料金改定等が返信案に自動反映される |
| Phase 3 | 実際に送信した文面を自動でナレッジに蓄積 | 使うほど言い回しが寄っていく |

### 見送った案

- **LINE 通知** — LINE Notify が 2025年3月に終了。現在は公式アカウント＋Messaging API が必要で、手間に見合わない。
- **ワンクリック送信** — 通知メールから直接送信する仕組み。誤送信リスクがあるため運用が固まるまで保留。

## 5. ③ 案件管理・案内メール

### 想定フロー（★＝システムが関与）

```
1. 見積もりフォーム回答          → ★案件一覧に行を自動生成
2. 初回返信（見積内容の確認）    → ★②のAIが返信案を生成
3. 質疑応答（数往復）            → ★②のAIが返信案を生成
4. 依頼確定                      → ステータスを手動で変更
5. Square で登録手数料 220円（税込）の請求書を作成・送付
6. 案内メール送付                → ★変数入力 → 下書き自動生成
7. 決済情報の登録・入金を確認
8. 商品到着 → 作業 → 返送
9. 月末締めで本請求
```

Phase 1 の自動化対象は 1〜6。

### 案件一覧シートの列（案）

| 区分 | 列 |
|---|---|
| 基本 | 受付日 / 会社名・屋号 / 担当者名 / メール / 電話 |
| 見積 | 選択オプション / 月間点数 / 単価 / 概算金額 |
| 進行 | ステータス / 次アクション / 最終更新日 |
| 変数 | 受付開始日 / 納期予定 / 発送予定日 / 実点数 |
| 請求 | 220円請求書URL / 送付日時 / 入金確認日 |
| その他 | メモ / Gmailスレッドへのリンク |

### 補助機能

- ステータスが一定期間動いていない案件を、毎朝メールで通知（対応漏れ防止）
- ステータスに応じた色分け表示

## 6. 運用ルール（2026-08-14 確定）

### 6-1. メールテンプレート

[メールテンプレート.md](メールテンプレート.md) に T1〜T7 の仮案を作成済み。
過去の案内メールは現存しないため、ヒアリング内容とサイト記載から起こした仮案。
スプレッドシート作成時に内容と変数位置を確認・修正する。

### 6-2. 220円の登録手数料

- 目的は **カード情報の保存と契約書への電子署名**。以降の請求→支払いを自動化するための手続き。
- Square の請求書送信機能から送る。件名は `サービスご利用における決済情報のご登録とご署名に関するお願い`。
- メッセージ欄の文面は T3。**スプレッドシートと本リポジトリの両方から確認・修正できるようにする。**
- **案内メール（T2）と同時に送付してよい。**
- 既存の請求書（Square 管理画面 → 請求書）と細かい設定をすべて揃える。
  設定内容を確認したら、実施前に必ず柴田様のチェックを仰ぐこと。
- 支払期限は現状設けていない。未完了の場合は T5 でリマインドする。

### 6-3. 受付開始日・納期予定

どちらも**感覚で都度判断**しているためルール化しない。
**手入力しないと案内メールを送れない設計**とする（空欄なら送信ボタンを無効化）。

### 6-4. 発送先・発送方法

ヤマト運輸の**営業所止め**。

| 項目 | 値 |
|---|---|
| 営業所コード | 160652 |
| 営業所名 | 松原柴垣営業所 |
| 郵便番号 | 580-0017 |
| 宛名 | 合同会社ケセラセラ |
| 電話番号 | スプレッドシート「設定」タブに保持（公開リポジトリには置かない） |
| 品名 | 衣類 |

- Web集荷の場合は営業所コードを入力。手書きラベルの場合は伝票右下の
  **「営業所受け取りサービス」にチェック**が必須。
- **梱包方法・発送方法は指定しない。** お客様が簡単に送れるようにするための配慮。
  発送時の送料をお客様負担としている理由の一つでもあるため、
  問い合わせで聞かれた際の回答材料として②のナレッジにも記載する。

### 6-5. 追跡番号の回収（課題への対応方針）

**課題**: 発送後に追跡番号を送ってもらいたいが、メール以外の顧客対応は増やしたくない。
一方でメール返信での連絡は忘れられやすい。

**方針**: 新しい窓口を作らず、**メールへの返信で完結**させる。

1. T2・T4 で「**このメールにそのまま返信**して追跡番号またはお控えの写真を送ってください」と依頼する。
   新しい画面を開かせないため、お客様の手間が最も少ない。
2. ②のメール監視が返信を検知し、**追跡番号らしき文字列（ヤマトの12桁）を自動抽出**して
   案件一覧に記録する。写真のみの場合は「要目視」として印を付ける。
3. 一定日数、追跡番号の連絡も荷物の到着もない場合、**T6 のリマインド下書きを自動生成**する。

この方式なら、お客様側の操作は「返信するだけ」、こちら側は「下書きを確認して送るだけ」で、
どちらの手間も増えない。

### 6-6. 作業開始の条件

**契約書への電子署名とカード登録（220円の決済）の両方を確認してから作業を開始する。**
このため案内メール（T2）では「ご発送の前にお手続きをお願いします」と案内し、
確認できた時点で T4 を送って発送を促す。
